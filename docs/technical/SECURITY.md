# امنیت
**مبنا:** کد مخزن، 2026-10-23. همه‌ی موارد از کد خوانده شده؛ آزمون نفوذ یا بازبینی مستقل انجام نشده است.

## هویت و نشست
- رمز با `bcryptjs`. توکن JWT در کوکی `auth_token` با `httpOnly`، `sameSite=lax`، `secure` در Production و عمر ۷ روز. `getAuthUser()` نقش و نام را از دیتابیس تازه می‌خواند.
- نقش‌ها: `student`، `professor`، `admin`. Authorization همیشه سمت سرور؛ admin فقط scope مجاز خود را می‌بیند (`adminScope.ts`، `permissions.ts`).
- `JWT_SECRET` اگر عوض شود همه‌ی نشست‌ها باطل می‌شوند (در انتقال سرور همان مقدار را نگه دارید).

## لایه‌ی درخواست
- `src/proxy.ts`: کنترل Origin/Referer برای CSRF و سقف بدنه (JSON ۱۰۰KB، multipart ۱۱MB). درخواست بدون هر دو هدر عبور می‌کند.
- محدودکننده‌ی نرخ برای ورود، ثبت‌نام، تغییر رمز، پیام چت، ساخت پروژه، درخواست عضویت، آپلود، گزارش و خطای مرورگر. همه در حافظه‌ی هر instance‌اند و سراسری نیستند.
- ثبت رویدادهای امنیتی با `auditLog` (مثل `login_rate_limited`، `seed_denied`، `dev_task_deleted`، `dev_task_code_analysis`).

## دستیار AI
- پنل و APIهای `/api/dev/*` فقط برای ایمیل‌های `DEV_ADMIN_EMAILS`؛ دیگران 404.
- `/api/cron/triage` با `Bearer CRON_SECRET` و بسته‌ماندن بدون راز.
- پیش از ارسال به مدل، متن با `maskForModel` پاک‌سازی می‌شود (رمز، توکن، ایمیل و شماره، مسیر و IP، کاراکترهای نامرئی و جهت‌دار، `<>`). متن کاربر در پرامپت «داده‌ی نامطمئن» است. تحلیل با کد فقط‌خواندنی است و فقط زیر `src/` با فهرست پسوند مجاز، و فایل‌هایی مثل `.env` ممنوع‌اند. جزئیات و نتیجه‌ی ارزیابی تزریق پرامپت (۱۰ از ۱۰ روی یک مدل): `AI_ASSISTANT.md`.

## فایل
دانلود فقط برای اعضای پروژه و استریم از برنامه؛ کلید شیء با الگوی سخت‌گیر؛ نوع و حجم کنترل‌شده (`STORAGE.md`).

## ریسک‌های شناخته‌شده
1. `/api/seed` راز را از query string هم می‌پذیرد (لاگ‌پذیر). پیشنهاد: فقط هدر.
2. نبود تأیید ایمیل، فراموشی/بازنشانی رمز، refresh token.
3. محدودکننده‌ها سراسری نیستند.
4. اگر `CRON_SECRET`، رمز دیتابیس، کلید AvalAI یا توکن GitHub در جای عمومی یا چت دیده شد، باید عوض شود.
5. هزینه‌ی واقعی و رفتار مدل روی داده‌ی واقعی بررسی کامل نشده است.
