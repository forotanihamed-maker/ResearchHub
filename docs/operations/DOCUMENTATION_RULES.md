# Documentation Rules

## Purpose

این سند مشخص می‌کند هر نوع اطلاعات ResearchHub در کجا نگهداری شود تا مستندات دوباره پراکنده و تکراری نشوند.

| موضوع | فایل |
|---|---|
| تعریف محصول | `docs/product/PRODUCT.md` |
| سیاست‌ها و تصمیم‌های محصول | `docs/product/PRODUCT_POLICIES.md` |
| وضعیت واقعی فعلی | `docs/product/CURRENT_STATE.md` |
| آینده و roadmap | `docs/product/ROADMAP.md` |
| معماری | `docs/technical/ARCHITECTURE.md` |
| دیتابیس | `docs/technical/DATABASE.md` |
| API | `docs/technical/API.md` |
| امنیت | `docs/technical/SECURITY.md` |
| deployment | `docs/technical/DEPLOYMENT.md` |
| تست و verification | `docs/technical/TESTING.md` |
| مدل کسب‌وکار | `docs/business/BUSINESS_MODEL.md` |
| Pilot | `docs/business/PILOT.md` |
| صنعت | `docs/business/INDUSTRY_LIAISON.md` |
| ساختار کد | `docs/development/PROJECT_STRUCTURE.md` |
| قواعد توسعه | `docs/development/DEVELOPMENT_RULES.md` |
| قواعد نگهداری مستندات | همین فایل |

## Rules

- یک موضوع فقط یک مرجع اصلی داشته باشد.
- README فقط خلاصه و navigation باشد.
- اطلاعات متناقض در چند فایل تکرار نشوند.
- Future feature در CURRENT_STATE نوشته نشود.
- Implementation fact در Product Policy به‌عنوان policy قطعی جا زده نشود.
- هر تغییر مهم محصول یا معماری باید سند مربوطه را هم به‌روزرسانی کند.
