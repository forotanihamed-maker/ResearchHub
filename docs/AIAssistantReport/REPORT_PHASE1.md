# گزارش مرحله ۱ — مدل داده دستیار هوش مصنوعی ResearchHub

**وضعیت:** تغییرات پیشنهادی مرحله ۱ آماده شده‌اند؛ اجرای آزمون‌های TypeScript/Build تأیید نشده است. این بسته را تا رفع پیش‌نیازهای مرحله صفر و بررسی انسانی، مستقیماً روی شاخه اصلی ادغام نکنید.

## مبنای کار

- مبنای تغییرات: فایل `ResearchHub-master-reviewed.zip` موجود در کتابخانهٔ گفتگو (نسخه‌ای که در ۱۶ اکتبر ۲۰۲۶ بارگذاری شده بود).
- فایل schema موجود و الگوی Migrationهای SQL پروژه بررسی شد.
- این snapshot الزاماً تضمین نمی‌کند که آخرین وضعیت شاخهٔ GitHub یا نسخهٔ محلی کاربر باشد.

## فایل‌های داخل بسته

1. `src/db/schema.ts` — افزودن enumها، جدول‌های جدید و روابط Drizzle.
2. `migrations/20261017_ai_service_assistant_phase1.sql` — SQL migration متناظر.

## مدل داده افزوده‌شده

- `issue_reports`
- `error_events`
- `ai_tasks`
- `ai_task_sources`
- `ai_analysis_runs`
- `ai_budget`
- `ai_tool_calls`
- `ai_pending_actions`

قواعد مهم:

- `issue_reports.user_id` و `ai_pending_actions.approved_by` با حذف کاربر به `NULL` تغییر می‌کنند.
- `ai_task_sources.source_id` چندریختی است و عمداً Foreign Key مستقیم ندارد؛ `source_type` تعیین می‌کند شناسه به گزارش یا خطا اشاره دارد.
- در `error_events` فیلدی برای body درخواست، cookie یا header محرمانه ایجاد نشده است.
- `ai_pending_actions` فقط ساختار ذخیره‌سازی دارد؛ هیچ منطق تأیید یا اجرای عملیاتی به این مرحله اضافه نشده است.
- `category` در گزارش‌ها و تسک‌ها به‌صورت `varchar` نگه داشته شده چون فهرست مجاز دسته‌ها در مشخصات تعیین نشده بود. وضعیت گزارش نیز `varchar` است تا گردش‌کار تأییدنشده‌ای به سیستم تحمیل نشود.
- هزینه‌ها و بودجه با `numeric` ذخیره می‌شوند تا از خطای گردکردن `float` جلوگیری شود.

## بررسی‌ها و آزمون‌ها

| بررسی | نتیجه واقعی |
|---|---|
| بررسی ساختار `schema.ts` و الگوی migrationهای قبلی در ZIP | انجام شد |
| ایجاد فایل SQL متناظر | انجام شد؛ دستی و مطابق سبک migrationهای موجود، نه با اجرای `drizzle-kit generate` |
| `npm ci --ignore-scripts` | تلاش شد اما فرایند به timeout ابزار رسید؛ وابستگی‌های اجرایی در محیط حاضر آماده نشدند |
| `tsc --noEmit` / `npm run typecheck` | اجرا نشد؛ `node_modules/.bin/tsc` در محیط کار حاضر نبود |
| ESLint | اجرا نشد |
| Vitest | اجرا نشد؛ در snapshot بررسی‌شده Vitest نصب و اسکریپت test تعریف نشده بود |
| `next build` | اجرا نشد |
| اجرای migration روی دیتابیس | انجام نشد؛ مطابق دستور، هیچ دیتابیس واقعی یا production تغییر نکرد |

## یافته‌های مرحله صفر که هنوز حل نشده‌اند

در snapshot بررسی‌شده:

- `src/lib/auditLog.ts` فاقد هشت رویداد `AuditEvent` ذکرشده در پیش‌نیاز بود.
- `eslint.config.mjs` موجود نبود.
- `src/middleware.ts` هنوز وجود داشت و به `src/proxy.ts` منتقل نشده بود.
- Vitest و اسکریپت `test` در `package.json` دیده نشدند.
- فایل `.github/workflows/ci.yml` در فهرست ZIP موجود نبود.

طبق سند اصلی، این موارد پیش‌نیاز مرحله صفر هستند. چون نصب وابستگی‌ها timeout شد و آزمون‌های لازم قابل اجرا نبودند، مرحله صفر هنوز سبز و تأییدشده نیست. این بسته فقط تغییرات مدل دادهٔ مرحله ۱ را دارد و نباید به‌عنوان ادغام کامل و آزمون‌شده معرفی شود.

## ریسک‌ها / نکات نیازمند بررسی

1. Migration با schema تطبیق داده شده است، اما تا اجرای `drizzle-kit generate` یا مقایسهٔ دقیق با خروجی آن، نباید ادعا کرد که migration خودکار Drizzle است.
2. قبل از merge باید `tsc`, `eslint`, `vitest` و `next build` روی آخرین checkout واقعی اجرا شوند.
3. باید تأیید شود که نام و قالب فایل‌های migration مطابق روند فعلی شاخهٔ مقصد است.
4. هیچ Secret، Environment Variable، Package یا دیتابیس production تغییر نکرده است.
5. هیچ commit یا push به GitHub انجام نشده است.

## پیشنهاد ادامه

ابتدا پیش‌نیازهای مرحله صفر را در checkout واقعی بررسی و تکمیل کنید. سپس این دو فایل را روی همان نسخهٔ تازه اعمال کنید، آزمون‌ها را اجرا کنید و تنها پس از بررسی انسانی، migration را در محیط مناسب اجرا کنید. اجرای production migration به تأیید جداگانهٔ مالک نیاز دارد.
