# بازبینی مرحله ۵ (دریافت ورودی‌ها) و اصلاح‌ها

پایه‌ی بررسی: فایل‌های `ResearchHub-Stage5-changed-files` به‌علاوه‌ی `fixed-files-v2` (نسخه‌ی v2 از `errorCapture.ts` و تستش) روی نسخه‌ی مرحله ۴. یعنی آخرین نسخه‌ی شما.

## نتیجه
کد شما روی چهار دستور سبز بود، ولی در آزمون واقعی روی Postgres **چهار ایراد** پیدا شد. هر چهار اصلاح و روی دیتابیس واقعی دوباره تأیید شد. ساختار، نام‌ها و دسته‌های فارسی شما حفظ شده است.

## ایرادهای پیدا‌شده

1. **سقف ۵۰۰۰ ردیف وارونه بود (جدی).** پاکسازی با `ORDER BY last_seen_at ASC … OFFSET 5000` ردیف‌های جدیدترین را حذف می‌کرد و ۵۰۰۰ قدیمی‌ترین را نگه می‌داشت.
   - آزمون واقعی: ۵۰۰۳ ردیف + یک خطای تازه ← خطای تازه فوراً حذف شد. یعنی بعد از رسیدن به سقف، ثبت خطا عملاً از کار می‌افتاد.
   - اصلاح: `DESC`، اجرا فقط وقتی fingerprint تازه است (قبلاً به‌ازای هر خطا، حتی تکراری‌ها)، و `await` شده (کار fire-and-forget روی serverless بعد از ارسال پاسخ ممکن است قطع شود).
   - بعد از اصلاح: ۵۰۰۰ ردیف، خطای تازه ماند، ۴ ردیف قدیمی‌تر حذف شد.

2. **توکن دعوت در `page_path` ذخیره می‌شد (جدی).** `/invite/<token>?token=abc` عیناً در `issue_reports.page_path` ذخیره شد. لینک دعوت یک دسترسی است.
   - اصلاح: query و fragment حذف و مقدارهای شبیه توکن ماسک می‌شوند. بعد از اصلاح ذخیره شد: `/invite/[REDACTED]`.
   - مسیر `//evil.io` هم رد می‌شود و بدنه‌ی بیش از ۱۶ کیلوبایت ← ۴۱۳ (قبلاً سقف اندازه نداشت).

3. **پنجره‌ی سقف نرخ به ساعت Node وابسته بود.** `created_at >= ${Date}` با ساعت JavaScript مقایسه می‌شد، ولی `created_at` با ساعت دیتابیس پر می‌شود. اگر منطقه‌ی زمانی Node و دیتابیس فرق کنند، پنجره جابه‌جا می‌شود. روی Vercel و Neon (هر دو UTC) دیده نمی‌شد.
   - اصلاح: پنجره و `Retry-After` کامل داخل SQL محاسبه می‌شود. `Retry-After` هم قبلاً همیشه ۳۶۰۰ بود؛ حالا زمان واقعی آزاد شدن اولین سهمیه است.
   - آزمون: Node با `TZ=UTC` و دیتابیس `Asia/Tehran`؛ ۵ گزارش به سن ۵۰ تا ۱۰ دقیقه ← گزارش ششم ۴۲۹ با `Retry-After: 600` (درست). پس از قدیمی‌شدن اولی به ۶۱ دقیقه ← ۲۰۱.

4. **تأیید تعاملی `apply-migration.mjs` گیر می‌کرد.** منتظر پایان stdin بود؛ در ترمینال با تایپ `YES` و Enter ادامه نمی‌داد (فقط با Ctrl+D / Ctrl+Z).
   - اصلاح: `readline.question`. آزمون با ترمینال شبیه‌سازی‌شده: بعد از `YES` + Enter اجرا شد.

## ایرادهای کوچک‌تر (اصلاح شد)
- ماسک‌کردن ضعیف: `Cookie: auth_token=…` و `session_token=…` و رشته‌های بلند مبهم ماسک نمی‌شدند. حالا می‌شوند.
- `sanitizeRoute` فقط چند نام query را می‌پوشاند؛ حالا کل query/fragment حذف می‌شود (مسیر `onRequestError` هم همین تابع را دارد).

## چیزهایی که تغییر ندادم (برای اطلاع)
- الگوی «سه بخش با نقطه» در v2 هر چیز شبیه `a.b.c` را ماسک می‌کند، مثل `next.config.ts` یا `10.20.30`. نشت نیست، فقط پیام‌های خطا گاهی بیش از حد سانسور می‌شوند. اگر آزاردهنده شد، می‌شود آن را به الگوی JWT واقعی (`eyJ…`) محدود کرد.
- شماره‌ی تلفن در پیام خطا ماسک نمی‌شود (در دستور مرحله نبود).
- `instrumentation.ts` با import ایستا کار می‌کند و build سبز است؛ تعویض `node:crypto` به WebCrypto در v2 را نگه داشتم.
- سقف نرخ `/api/errors` در حافظه‌ی هر instance است (همان‌طور که خودتان نوشته بودید).
