# گزارش مرحله ۴ — دسترسی به پنل دستیار توسعه‌دهنده (فقط مالک)

## هدف
پنل `/dashboard/dev/*` و `/api/dev/*` فقط برای ایمیل‌های فهرست‌شده در `DEV_ADMIN_EMAILS` باز باشد. ادمین دانشکده، استاد، دانشجو و کاربر بدون ورود چیزی از پنل نبینند. در این مرحله هیچ قابلیت AI ساخته نشده؛ فقط قفل دسترسی و یک صفحه/API نمونه.

## فایل‌ها (۱۰ فایل)
| فایل | تغییر |
|---|---|
| `src/lib/devAccess.ts` (جدید) | منطق دسترسی. `requireDevPanelUser(where)` برای صفحه/layout (۴۰۴ با notFound)، `getDevApiUser(where)` + `devNotFoundResponse()` برای APIها (۴۰۴ خالی و قطعی)، و `isDevAdminEmail`. |
| `src/lib/devAccess.test.ts` (جدید) | ۱۷ آزمون. |
| `src/lib/auditLog.ts` | دو رویداد `dev_panel_access` و `dev_panel_denied` اضافه شد. |
| `src/app/api/dev/me/route.ts` (جدید) | API نمونه: ۲۰۰ برای مالک، ۴۰۴ برای بقیه. |
| `src/app/dashboard/dev/layout.tsx` (جدید) | محافظ سمت سرور. |
| `src/app/dashboard/dev/tasks/page.tsx` (جدید) | صفحه‌ی نمونه، با محافظ جداگانه (layout به‌تنهایی کافی نیست). |
| `src/components/layout/Sidebar.tsx` | آیتم «دستیار توسعه‌دهنده» فقط وقتی `user.devPanel === true`. |
| `src/contexts/AuthContext.tsx` | فیلد اختیاری `devPanel` در نوع User. |
| `src/app/api/auth/me/route.ts` | فقط GET: فیلد `devPanel` به پاسخ اضافه شد (فقط راهنمای UI). |
| `.env.example` (جدید) | `DEV_ADMIN_EMAILS=` |

## قواعد
- ایمیل‌ها با کاما جدا می‌شوند؛ مقایسه بدون حساسیت به حروف و دقیق (پسوند یا پیشوند اضافه قبول نیست).
- متغیر خالی یا تنظیم‌نشده = هیچ‌کس دسترسی ندارد (fail closed).
- کاربر از `getAuthUser()` می‌آید که هر بار از دیتابیس می‌خواند؛ تغییر ایمیل یا حذف حساب دسترسی را از درخواست بعد قطع می‌کند.
- هر دسترسی و هر رد در audit log ثبت می‌شود. ردها هرگز ایمیل ندارند (فقط where، reason، userId، role).

## نتایج واقعی
- `typecheck`: بدون خطا. `lint --quiet`: ۰ خطا. تست‌ها: ۴۱ پاس (۲۴ قبلی + ۱۷ جدید). build: موفق (با layout موقت در سندباکس).
- آزمون HTTP واقعی (سرور production محلی، Postgres، `DEV_ADMIN_EMAILS=Admin@ResearchHub.ir`):

| کاربر | `/api/dev/me` | `auth/me → devPanel` |
|---|---|---|
| مالک (ادمین با ایمیل لیست‌شده، حروف متفاوت) | 200 | true |
| ادمین دانشکده | 404 | false |
| استاد | 404 | false |
| دانشجو | 404 | false |
| بدون ورود | 404 | — |

- صفحه‌ی `/dashboard/dev/tasks`: برای مالک محتوا نمایش داده شد؛ برای دانشجو و بدون‌ورود بدنه شامل صفحه‌ی ۴۰۴ بود و متن صفحه‌ی پنل در پاسخ **نبود** (نشت محتوا ندارد).
- لغو دسترسی: ایمیل مالک را در دیتابیس عوض کردم؛ با همان توکن قبلی، API ۴۰۴ داد و صفحه محتوا نداد.
- audit log سرور: ردها بدون هیچ ایمیل.

## محدودیت‌ها (صادقانه)
- **کد وضعیت HTTP صفحه** برای غیرمجاز ۲۰۰ می‌ماند، ولی بدنه صفحه‌ی ۴۰۴ است و محتوای پنل ارسال نمی‌شود. دلیل: layout اصلی `/dashboard` یک Client Component است و پوسته را زودتر stream می‌کند. APIها ۴۰۴ واقعی می‌دهند. اگر ۴۰۴ واقعی برای صفحه لازم شد، باید محافظ به سطح دیگری (مثلاً route group جدا) برود.
- ظاهر صفحه و آیتم سایدبار در مرورگر دیده نشد (فقط build/تست).
- مالک با ایمیل تعریف می‌شود و ثبت‌نام تأیید ایمیل ندارد. اگر ایمیل مالک هنوز حساب ثبت‌شده نداشته باشد، هر کس می‌تواند با آن ایمیل ثبت‌نام کند و به پنل برسد. پس ایمیلی در `DEV_ADMIN_EMAILS` بگذارید که از قبل حساب واقعی خودتان است.
- هنوز به دیتابیس production دست نخورده.

## راه‌اندازی
1. فایل‌ها را جایگزین کنید.
2. در `.env.local` (و در Vercel) بگذارید: `DEV_ADMIN_EMAILS=ایمیل-حساب-خودتان`
3. سرور را دوباره بالا بیاورید، با همان حساب وارد شوید؛ باید آیتم «دستیار توسعه‌دهنده» در سایدبار بیاید و `/dashboard/dev/tasks` باز شود.
4. با یک حساب دیگر (مثلاً دانشجو) وارد شوید؛ نه آیتم را ببینید نه صفحه را.
