# مرحله ۷ — پنل تسک‌های توسعه‌دهنده

## چه ساخته شد
- صفحه‌ی `/dashboard/dev/tasks` (فقط ایمیل‌های `DEV_ADMIN_EMAILS`؛ دیگران ۴۰۴):
  - نوار هزینه‌ی ماه (مصرف از سقف، تعداد فراخوانی) و دکمه‌ی «توقف اضطراری / فعال‌سازی دوباره» (kill switch، با تأیید قبل از توقف).
  - فهرست تسک‌ها، مرتب بر اساس اهمیت (بحرانی ← کم) و بعد جدیدترین؛ فیلتر وضعیت و اولویت؛ صفحه‌بندی ۲۰تایی.
  - جزئیات هر تسک: خلاصه، پیشنهاد رفع («فقط پیشنهاد»)، میزان اطمینان، متن گزارش یا خطای منبع، مدل‌ها و هزینه‌ی تحلیل.
  - تغییر وضعیت: باز / در حال انجام / حل‌شده / ردشده.
- APIها: `GET /api/dev/tasks`، `GET|PATCH /api/dev/tasks/[id]` (فقط status)، `GET|PATCH /api/dev/budget` (فقط killSwitch).
- هر API با `getDevApiUser` شروع می‌شود؛ دیگران ۴۰۴ می‌گیرند. فیلترهای ناشناخته نادیده گرفته می‌شوند و هرگز به SQL نمی‌رسند.
- نام یا ایمیل نویسنده‌ی گزارش هیچ‌جا نمایش داده نمی‌شود (join با users ندارد).
- سقف هزینه عمداً از وب قابل تغییر نیست؛ فقط با `scripts/ai-budget.mjs --cap`.
- دو رویداد audit: `dev_task_status_changed`، `ai_kill_switch_changed`. تغییر schema: ندارد.

## بررسی‌ها
- typecheck بدون خطا؛ تست‌ها: همه موفق (۹۲ قبلی + ۶ جدید)؛ lint ۰ خطا.
- روی Postgres واقعی و سرور build‌شده: بدون ورود/دانشجو ← ۴۰۴ برای هر ۵ مسیر؛ مالک ← فهرست، فیلتر، جزئیات، PATCH؛ وضعیت نامعتبر ← ۴۰۰؛ تسک ناموجود ← ۴۰۴؛ Origin بیگانه ← ۴۰۳؛ تغییر وضعیت و kill switch در دیتابیس ثبت شد.
- در مرورگر واقعی (Chromium): مالک پنل را می‌بیند، تسک را باز می‌کند و وضعیت را تغییر می‌دهد (در دیتابیس ماندگار شد)؛ دانشجو صفحه‌ی ۴۰۴ می‌بیند.

## نکته‌ی فنی
وضعیت HTTP صفحه‌ی `/dashboard/dev/*` برای غیرمجاز، ۲۰۰ با محتوای «۴۰۴» است نه کد ۴۰۴ (چون لایه‌ی `dashboard/layout` سمت کلاینت است). محتوا و دسترسی درست است؛ APIها کد ۴۰۴ واقعی می‌دهند.
