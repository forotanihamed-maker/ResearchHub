# گزارش Stage 3 — قفل‌کردن تغییر دانشکده‌ی ادمین (فقط مالک سامانه)

## فایل‌های تغییرکرده (فقط ۴ فایل)
| فایل | تغییر |
|---|---|
| `src/app/api/admin/departments/route.ts` | PATCH: بعد از ۴۰۱/۴۰۳ نقش، برای هر ادمین ۴۰۳ با پیام «تعیین گروه‌های آموزشی فقط توسط مالک سامانه انجام می‌شود.». بدنه خوانده نمی‌شود و هیچ query/transaction اجرا نمی‌شود. GET دست‌نخورده. |
| `src/app/dashboard/admin/departments/page.tsx` | فقط‌خواندنی: برچسب دانشکده‌ها، بدون دکمه‌ی ذخیره/انتخاب؛ پیام تماس با مالک؛ حالت «بدون دانشکده» با پیام روشن. |
| `scripts/set-admin-departments.sql` (جدید) | اسکریپت مالک برای تعیین دانشکده‌ی یک ادمین. |
| `src/lib/adminDepartmentsLock.test.ts` (جدید) | ۵ آزمون Vitest. |

## نتیجه‌ی واقعی دستورها (روی دیتابیس آزمایشی محلی)
- `npm run typecheck`: بدون خطا
- `npm test`: ۳ فایل، ۲۴ آزمون پاس (۱۹ قبلی + ۵ جدید)
- `npm run lint -- --quiet`: ۰ خطا
- `npm run build`: موفق (با layout موقت چون Google Fonts در سندباکس من بسته است؛ layout اصلی برگردانده شد). روی ماشین خودتان build را دوباره بگیرید.

## آزمون واقعی HTTP (سرور production محلی + Postgres)
ادمین با یک دانشکده («علوم داده») و ۴۵ پروژه‌ی قابل‌مشاهده:
- PATCH با هر ۶ دانشکده ← **۴۰۳** با پیام مالک
- بعد از آن: دانشکده‌ها هنوز `['علوم داده']` و پروژه‌ها هنوز ۴۵ (قبل از Stage 3 همه‌ی ۶ را می‌گرفت)
- PATCH بدون ورود ← ۴۰۱

## آزمون اسکریپت SQL (دیتابیس آزمایشی)
| ورودی | نتیجه |
|---|---|
| ایمیل با حروف بزرگ و فاصله + ۲ دانشکده | موفق، دقیقاً ۲ ردیف برای همان ادمین |
| اجرای دوباره همان ورودی | همان نتیجه (idempotent) |
| ایمیل ناموجود | خطا، بدون تغییر |
| کاربر غیرادمین (دانشجو) | خطا، بدون تغییر |
| دانشکده‌ی نامعتبر («فیزیک») | خطای enum، rollback کامل |
| آرایه‌ی خالی `{}` | خطا، بدون تغییر |
ردیف‌های ادمین‌های دیگر در همه‌ی حالت‌ها دست‌نخورده ماند.

## روش استفاده‌ی مالک
```
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 \
  -v admin_email='x@y.z' \
  -v depts='{"هوش مصنوعی","علوم داده"}' \
  -f scripts/set-admin-departments.sql
```
اول روی دیتابیس آزمایشی. روی Neon اصلی فقط خودتان و پس از اطمینان.

## اعلام‌ها
- فایل خارج از Scope تغییر نکرد. schema و migration عوض نشد.
- به دیتابیس production دست نخورد؛ همه‌چیز روی Postgres محلی سندباکس.
- تست نشد: رندر بصری صفحه در مرورگر (فقط typecheck/build)، و اجرای اسکریپت روی Neon.

## یافته‌های جانبی (تغییر نداده‌ام)
- ادمینی که دانشکده ندارد هیچ داده‌ای نمی‌بیند؛ پس بعد از دیپلوی، برای هر ادمین واقعی یک‌بار اسکریپت را اجرا کنید.
- `/api/seed` همچنان همه‌ی دانشکده‌ها را به ادمین seed می‌دهد؛ آن route را در production غیرفعال یا محافظت‌شده نگه دارید.
