# ResearchHub — Product Policies

> این سند سیاست‌های مطلوب/تصمیم‌های محصول را ثبت می‌کند. برای دیدن اینکه کدام سیاست‌ها همین الان در کد enforce می‌شوند، `CURRENT_STATE.md` را ببینید.

## 1. Visibility

- دانشجو پروژه‌های قابل مشاهده در محدوده دانشکده خود را می‌بیند.
- پروژه عمومی برای کشف و درخواست عضویت قابل مشاهده است.
- محتوای داخلی پروژه عمومی برای غیرعضو عمومی نیست.
- پروژه خصوصی فقط برای افراد مجاز قابل مشاهده است.
- پروژه‌های شخصی دانشجو بدون اجازه او نباید برای ادمین قابل مشاهده باشند.
- پروژه بین‌دانشکده‌ای برای ادمین‌های دانشکده‌های مرتبط قابل پایش است.

## 2. Discovery Filters

دانشجو باید بتواند پروژه‌های قابل مشاهده را بر اساس موارد زیر فیلتر کند:

- حوزه تخصصی
- استاد
- نوع پروژه
- مهارت‌های موردنیاز

## 3. Membership

- دانشجو برای پروژه عمومی درخواست عضویت می‌فرستد.
- استاد درخواست را approve/reject می‌کند.
- دانشجو هنگام درخواست می‌تواند متن معرفی/دلیل تناسب خود را بفرستد.
- پس از تأیید، عضو به محتوای داخلی پروژه دسترسی می‌گیرد.
- پس از رد، دانشجو حداکثر دو بار برای همان پروژه می‌تواند درخواست بدهد.
- بین دو درخواست محدودیت زمانی تعیین نشده است.

## 4. Capacity

- سازنده ظرفیت پروژه را تعیین می‌کند.
- ظرفیت سقف تعداد اعضای غیرسازنده است.
- ظرفیت پس از انتشار قابل افزایش است.
- ظرفیت نمی‌تواند از تعداد اعضای فعلی کمتر شود.

## 5. Deadline

- مهلت درخواست عضویت اختیاری است.
- پس از پایان مهلت، دعوت مستقیم استاد همچنان ممکن است.

## 6. Private Invitations

- دعوت با شناسه کاربری یا لینک انجام می‌شود.
- سیاست نهایی درباره لغو لینک هنوز باز است.
- سیاست «یک‌بارمصرف/شخص‌محور» به‌عنوان تصمیم محصول ثبت شده، اما پیاده‌سازی فعلی نیازمند تطبیق است.

## 7. Closing

- استاد می‌تواند پروژه را ببندد.
- پروژه Pause نمی‌شود.
- دلیل بسته‌شدن الزامی و متنی است.
- دلیل برای اعضای پروژه قابل مشاهده است.
- پروژه بسته‌شده نباید دوباره فعال شود.
- پروژه بسته‌شده نباید توسط افراد غیرعضو قابل مشاهده باشد.
- اعضای جدید پس از بسته‌شدن نمی‌توانند وارد شوند.
- اطلاعات و مستندات پس از بسته‌شدن باید immutable شوند.
- اعضای قبلی همچنان باید بتوانند سابقه و مستندات را ببینند.

## 8. Open Decisions

- شرایط دقیق حذف عضو توسط استاد
- شرایط دقیق خروج دانشجو
- سیاست نهایی لغو/rotate لینک دعوت
- workflow اختصاصی انواع پروژه
- سیاست دقیق ویرایش پروژه پس از انتشار
- سطح دقیق دسترسی ادمین به پروژه‌های خصوصی
