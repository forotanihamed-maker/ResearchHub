# وضعیت فعلی ResearchHub

**مبنای این سند:** بررسی ایستای ZIP دریافت‌شده در 2026-09-26. این بررسی فایل‌ها و مسیرهای موجود را بررسی می‌کند؛ اجرای برنامه، اتصال به Neon و رفتار محیط Production در این بررسی آزمایش نشده‌اند.

## وضعیت کلی
ResearchHub در مرحله MVP/اعتبارسنجی است. کدهای اصلی محصول و فضای اجرای پروژه در Repository وجود دارند. وجود فایل/route به‌تنهایی تضمین نمی‌کند که قابلیت در Production درست کار می‌کند؛ تأیید نهایی نیازمند typecheck، build، بررسی دستی و تست با سرویس‌های واقعی است.

## قابلیت‌هایی که پیاده‌سازی آن‌ها در کد قابل مشاهده است
- احراز هویت و نقش‌های `student`، `professor` و `admin`.
- پروژه‌ها، اعضای پروژه، درخواست‌ها و دعوت‌ها.
- پیام‌های پروژه، فایل‌های پروژه و پیام مستقیم ادمین/استاد.
- پنل‌های مدیریتی برای دپارتمان‌ها، استادها، پروژه‌ها، آمار و نمای کلی دانشکده.
- فضای اجرای پروژه: Tasks، Milestones، Activity و Project Overview.
- API سلامت در `/api/health`.
- مسیر seed محافظت‌شده با `SEED_SECRET`؛ به‌دلیل اثر مخرب احتمالی، فقط با احتیاط و پس از بازبینی امنیتی استفاده شود.

## فناوری و ساختار تأییدشده از فایل‌ها
- Next.js App Router، React، TypeScript.
- PostgreSQL و Drizzle ORM.
- JWT با کوکی `auth_token` و `bcryptjs`.
- TanStack React Query.
- Vercel Blob برای فایل‌های پروژه.
- کد اصلی در `src/app`، `src/components`، `src/contexts`، `src/db` و `src/lib` قرار دارد.
- Migrationهای پایه در `drizzle/` و migrationهای بعدی در `migrations/` قرار دارند.

## قابلیت‌هایی که در این ZIP پیاده‌سازی نشده‌اند
- دستیار توسعه‌دهنده‌ی هوش مصنوعی: دریافت گزارش مشکل، ثبت خودکار خطاهای سرور/کلاینت، پردازش AI، ذخیره تسک‌های AI و پنل `/dashboard/dev/tasks` در کد وجود ندارند.
- GitHub Actions workflow برای زمان‌بندی یا CI در `.github/workflows/` در این ZIP وجود ندارد.
- تست خودکار: در `package.json` اسکریپت `test` یا `eval:triage` و در ZIP فایل تستی پیدا نشد.

موارد بالا صرفاً درباره ZIP بررسی‌شده‌اند و وضعیت مخزن زنده ممکن است متفاوت باشد.

## بررسی‌هایی که هنوز اجرا نشده‌اند
در این مرحله `npm run typecheck`، `npm run lint`، `npm run build`، تست ورود و نقش‌ها، تست APIها، اتصال به Neon، Vercel Blob و بررسی محیط Production اجرا نشده‌اند. بنابراین نباید وضعیت Build/Production را «تأییدشده» اعلام کرد.

## ریسک‌ها و کارهای پیگیری
1. بررسی endpoint `/api/seed`: در کد، راز از طریق query string نیز پذیرفته می‌شود؛ این روش می‌تواند باعث ثبت راز در history، log یا ابزارهای مانیتورینگ شود. پیشنهاد: حذف پشتیبانی query string و پذیرش secret فقط از header، همراه با بررسی محدودیت دسترسی.
2. محدودکننده نرخ در `src/lib/rateLimit.ts` در حافظه‌ی همان instance است؛ در serverless محدودیت سراسری و پایدار ایجاد نمی‌کند.
3. قبل از Pilot واقعی، تست‌های یکپارچه و امنیتی حداقلی و اجرای typecheck/build لازم است.
4. قبل از توسعه دستیار AI، مسیرهای مستندات باید یکتا شوند و قراردادهای واقعی auth، schema، rate limit و مجوزهای پنل توسعه‌دهنده بازبینی شوند.

## قاعده نگهداری
پس از هر تغییر بزرگ، این سند را با Repository و نتایج واقعی تست‌ها تطبیق دهید. ایده یا سند طراحی نباید به‌عنوان قابلیت پیاده‌سازی‌شده معرفی شود.
