# ResearchHub — راهنمای نصب و اجرا (برای توسعه‌دهنده)

## پیش‌نیازها

- Node.js (نسخه‌ای سازگار با Next 16 / React 19 — نصب کنید `node -v` و اگر مشکلی دید، آخرین LTS را بگیرید)
- یک دیتابیس PostgreSQL — پروژه با **Neon** تست شده، ولی هر Postgres دیگری هم باید کار کند
- npm

## ۱. نصب وابستگی‌ها

```bash
npm install
```

## ۲. متغیرهای محیطی

یک فایل `.env.local` در ریشه‌ی پروژه بسازید (کنار `package.json`) با این محتوا:

```dotenv
DATABASE_URL=postgresql://user:password@host/dbname?sslmode=require

JWT_SECRET=یک-رشته‌ی-تصادفی-طولانی-و-امن
JWT_EXPIRES_IN=7d

SEED_SECRET=یک-رشته-تصادفی-دیگر
```

| متغیر | اجباری؟ | توضیح |
|---|---|---|
| `DATABASE_URL` | بله | اتصال Postgres، باید `sslmode=require` داشته باشد اگر Neon است |
| `JWT_SECRET` | بله | برای امضای توکن لاگین؛ اگر نباشد کل احراز هویت کار نمی‌کند |
| `JWT_EXPIRES_IN` | خیر (پیش‌فرض کد را چک کنید) | مدت اعتبار توکن، فرمت `jsonwebtoken` (مثل `7d`, `12h`) |
| `SEED_SECRET` | فقط برای استفاده از `/api/seed` | بدون این، آن route همیشه ۴۰۴ می‌دهد |

### ⚠️ نکته‌ی حیاتی: کاراکتر `$` در `.env.local`

Next.js به‌صورت پیش‌فرض کاراکتر `$` در فایل‌های `.env*` را به‌عنوان ارجاع به متغیر دیگر تفسیر می‌کند (شبیه متغیر شل). اگر مقدار `JWT_SECRET` یا `SEED_SECRET` شما شامل `$` باشد، حتماً با بک‌اسلش escape کنید:

```dotenv
# اشتباه — بخشی از مقدار به‌خاطر $ حذف می‌شود
SEED_SECRET=Abc$123xyz

# درست
SEED_SECRET=Abc\$123xyz
```

**هر بار که `.env.local` را تغییر می‌دهید، باید `npm run dev` را کامل متوقف (Ctrl+C) و دوباره اجرا کنید** — Next.js متغیرهای محیطی را فقط در لحظه‌ی استارت سرور می‌خواند، نه به‌صورت زنده.

## ۳. ساخت جداول دیتابیس (Migration)

دو فایل migration در پروژه هست که باید هر دو به‌ترتیب روی دیتابیستان اجرا شوند:

```
src/drizzle/0000_nervous_malcolm_colcord.sql     ← جداول پایه
src/migrations/20260818_admin_panel.sql          ← جداول پنل ادمین
```

اگر از `drizzle-kit` استفاده می‌کنید:
```bash
npx drizzle-kit push
```
این دستور schema را مستقیم با فایل `src/db/schema.ts` هماهنگ می‌کند. اگر ترجیح می‌دهید فایل‌های SQL را دستی روی دیتابیس اجرا کنید (مثلاً از طریق کنسول Neon)، هر دو فایل بالا را به‌ترتیب paste و اجرا کنید.

می‌توانید با این آدرس (بعد از راه‌اندازی سرور) تأیید کنید هر دو migration درست نشسته‌اند:
```
GET /api/seed?secret=YOUR_SEED_SECRET&action=check-schema
```

## ۴. اجرای سرور توسعه

```bash
npm run dev
```
روی `http://localhost:3000` بالا می‌آید.

## ۵. پر کردن داده‌ی نمونه (اختیاری، برای تست/دمو)

```
http://localhost:3000/api/seed?secret=YOUR_SEED_SECRET
```
اگر دیتابیس خالی باشد، خودکار داده‌ی نمونه می‌سازد (اساتید، دانشجویان، پروژه‌ها، پیام‌ها). حساب‌های دمو دقیقاً همان‌هایی هستند که در `src/app/auth/login/page.tsx` (آرایه‌ی `DEMO_ACCOUNTS`) و `PILOT_SETUP.md` مستند شده‌اند — **این سه منبع باید همیشه با هم هماهنگ بمانند**؛ اگر ایمیل دمویی را تغییر می‌دهید، هر سه‌جا را آپدیت کنید.

برای دیدن کاربران واقعاً موجود در دیتابیس بدون تغییر دادن چیزی:
```
http://localhost:3000/api/seed?secret=YOUR_SEED_SECRET&action=list
```

## ۶. دستورات مفید دیگر

```bash

npm run build        # build تولیدی (همانی که Vercel اجرا می‌کند)

```

## ۷. دیپلوی روی Vercel

- تمام متغیرهای بخش ۲ باید در تنظیمات محیطی پروژه‌ی Vercel هم ست شوند (فایل `.env.local` روی Vercel آپلود نمی‌شود).
- `vercel.json` تنظیمات دیپلوی را دارد — نیازی به تغییر دستی معمولاً نیست.
- به‌خاطر داشته باشید: rate-limiting فعلی درون‌حافظه‌ای است (به `ARCHITECTURE.md` بخش ۷ نگاه کنید) — روی Vercel serverless این محافظت تضمین‌شده‌ی سراسری نیست، فقط لایه‌ی دفاعی اولیه است.

## ۸. مشکلات رایج

| علامت | دلیل محتمل |
|---|---|
| `{"error":"Not found"}` از `/api/seed` | یا `SEED_SECRET` در `.env.local` نیست، یا سرور بعد از تغییر `.env.local` ری‌استارت نشده، یا مقدار `secret` در URL دقیقاً با فایل مطابقت ندارد (مراقب کاراکتر `$` و `&` باشید — `&` در URL باید `%26` بشود) |
| لاگین با «Invalid email or password» برای کاربری که مطمئنید درست است | دیتابیس با یک نسخه‌ی قدیمی‌تر از `seed.ts`/`api/seed/route.ts` پر شده و ایمیل واقعی با چیزی که در `DEMO_ACCOUNTS` صفحه‌ی لاگین است فرق دارد؛ با `?action=list` چک کنید |
| پنل ادمین خالی/صفر نشان می‌دهد | حساب ادمینی که با آن لاگین کرده‌اید هیچ دپارتمانی در `admin_departments` ندارد — از `/dashboard/admin/departments` دپارتمان تخصیص دهید |
